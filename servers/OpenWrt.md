## Сервисы и границы доступа

| Сервис | Где слушает | Назначение и состояние |
| --- | --- | --- |
| [[SSH]] / Dropbear | TCP `22`, все интерфейсы | Администрирование; 12 октября вход root с ранее работавшим паролем отклонялся. |
| `uhttpd` / LuCI | TCP `80/443`, все интерфейсы | Веб-панель роутера. Реальная достижимость с WAN зависит от firewall. |
| `ttyd` | TCP `7681` на `192.0.2.1` | Веб-терминал только на адресе LAN. |
| [[DNS и DHCP]] | DNS TCP/UDP `53` на адресах роутера; DHCP UDP `67`, DHCPv6 UDP `547` | `dnsmasq` и `odhcpd` обслуживают сеть. |
| [[WireGuard и wanroute]] | Туннель/маршрутизация | `wg` активен; выбранный трафик уходит напрямую через WAN. |
| Firewall / `netifd` | Локальные службы | Управляют интерфейсами, зонами и правилами. |
| `adblock` | Локальный пакет | Установлен, но статус показывает ошибку и ноль заблокированных доменов. |

## Маршрутизация

Основная таблица: `203.0.113.0/24`, `198.18.20.0/24`, `198.18.30.0/24` и `198.18.40.0/24` через `198.51.100.2`; default route через `wg`. В таблице `wanroute` default route идёт через WAN-шлюз `192.0.2.1`.

`ip rule` направляет `203.0.113.0/24` через `wanroute`, кроме ответов в домашнюю LAN; `198.18.40.10` через `wanroute`; `198.51.100.2 → 203.0.113.10` через `wanroute` для [[FRP]] после SNAT на AXGATE. Для тестовой сети добавлено постоянное правило `network.vm_nat_wan`: трафик с источником `198.51.100.2/32`, пришедший через `lan4`, использует таблицу `wanroute` (приоритет 30011). На зоне `lan` masquerade включён, для связи с trust/print есть NAT-исключения. Зона `transit` привязана к `lan4` и разрешает input/output/forward. Статических port forward к [[Server1 Banana Pi]] в конфигурации не найдено; UPnP выключен.

Для сети game добавлена постоянная UCI-запись `network.ps4_route`: `198.18.40.0/24` через `198.51.100.2` на `lan4`. Маршрут сразу применён в ядре. До исправления `ip route get 198.18.40.10` выбирал `wg`; после исправления выбирает AXGATE, а трассировка из домашней LAN достигает `198.18.40.1` за два перехода. AXGATE видит ответные DNS-пакеты и HTTPS-трафик PS4; пользователь подтвердил, что после повторного теста всё работает.

Для сети test добавлена постоянная UCI-запись `network.vmtest_route`: `198.18.20.0/24` через `198.51.100.2` на `lan4`. Маршрут и правило `vm_nat_wan` сразу применены в ядре; после этого Arch VM `198.18.20.21` успешно проверила ICMP к `1.1.1.1` и HTTPS к `archlinux.org`. Конфигурация сохранена командой `uci commit network`, но перезапуск `netifd` после изменения не выполнялся; при следующей перезагрузке роутера нужно подтвердить сохранение маршрута и правила.

Связанные узлы: [[Server1 Banana Pi]], [[AXGATE 80D]], [[Server2]], [[Eltex NV-501-WAC]].
